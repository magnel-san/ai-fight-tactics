# AI Fight Tactics 仕様書

Oct 5, 2026 · @まぐ

## 1. 概要とゲームループ

ブロックで組んだモンスターを機械学習で育て、崩落していく六角形タイルのステージで最後まで生き残った方が勝つ、PCブラウザ向けの対戦ゲームです。WindowsとMacのブラウザで動作し、URLを送るだけで友人に配布できることを目指します。

プレイヤーは次のループを繰り返します。

1. **キャラクリエイト**:コアブロックを起点に、基礎・関節・ピストン・弾力・雲・浮力・センサーの各ブロックをコスト上限内で組み合わせて体を作る。ブロックごとに形(立方体・球・円柱)と摩擦オンを選べる。
2. **トレーニング**:メニューを順に解放しながら学習させ、世代ごとに上達していく様子を観戦する。
3. **バトル**:BOTや友人のキャラと、崩落ステージで生き残りを競う。
4. **見直し**:負けた原因に応じて、体を組み直すか、トレーニングを積み直す。

対象外とするもの:iOS・Androidなどのモバイル対応、タッチ操作、HPやダメージの概念、能動的なバネブロック(将来の追加候補)。

## 2. 技術スタックと配布方法

TypeScriptで書いた静的なWebアプリとして作り、サーバーなしで配布します。学習もプレイヤーのブラウザ内で完結させます。

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript | 型で物理・脳・データ形式の整合を守る |
| ビルド | Vite | 設定が少なく、Web Workerの扱いが簡単 |
| 3D描画 | Three.js | 実績が多く、Claude Codeが扱い慣れている |
| 物理 | Rapier(@dimforge/rapier3d-compat) | WASM製で高速、決定論的なシミュレーションが可能 |
| 並列学習 | Web Worker | 描画を止めずに多数の個体を同時に評価する |
| UI | React | メニュー、HUD、グラフ |
| テスト | Vitest、Playwright | ロジックの単体テストと、ブラウザ間の決定性テスト |
| ローカル保存 | IndexedDB | キャラ、学習履歴、リプレイを保存 |
| 配布 | itch.io または GitHub Pages | 静的ファイルを置くだけで埋め込みも可能 |
| オンライン(後期) | Supabase | キャラ登録と非同期対戦 |

対応ブラウザは、Windows・Mac上の最新版Chrome、Edge、Firefox、Safariとします。

## 3. アーキテクチャとディレクトリ構成

ゲームの中核ロジックを、描画やDOMに依存しない「決定論的コア」として分離します。同じコアをメインスレッド(観戦・バトル表示)と学習用Worker(描画なしの高速評価)の両方で動かすことで、学習中に評価した試合を、そのまま表示用に再現できます。

- **メインスレッド**:Three.jsでの描画、UI、観戦用の再シミュレーション。
- **学習Worker**:CPUコア数に応じて複数起動し、各Workerが自分のRapierワールドで個体を評価する。
- **決定論的コア**:物理、ステージ、脳、学習アルゴリズム。`three`やDOMをimportしてはいけない。

```
src/
  core/                 決定論的コア(three・DOM非依存)
    creature/           設計図、剛体の組み立て、コスト計算
    physics/            Rapierワールドの初期化、固定ステップ
    stage/              六角グリッド、崩落ルール
    brain/              MLP、運動脳、判断脳、センサー
    sim/                試合・エピソードの実行ループ
    training/           遺伝的アルゴリズム、トレーニング課題と報酬
    math/               シード付き乱数、決定論的な数学関数
  workers/
    training.worker.ts  学習用Worker
  render/               Three.jsのシーン、ゴースト表示、カメラ
  scenes/
    create/             キャラクリエイト
    train/              トレーニング
    battle/             バトル
  ui/                   Reactコンポーネント
  storage/              IndexedDB、共有コード
tests/                  単体テスト、決定性テスト
docs/SPEC.md            この仕様書
```

## 4. キャラクリエイトとブロック仕様

キャラはコアブロックを根とする木構造で、総コスト40以内で組み立てます。ブロックは1辺0.4mの格子に置き、既存ブロックの面に吸着して配置します。
形は立方体(角を半径0.06mで丸めたもの)・球(直径0.4m)・円柱(直径0.4m・長さ0.4m)から選べます。重さは形によらず同じです。
円柱の軸の向きは、自動(関節なら回転軸で車輪になる、ピストン・風なら向き、ほかのブロックは付けた面の向き、コアは上下)か、左右・上下・前後から選べます。
円柱にした関節は「タイヤモード」にできます(半径を1.5倍の0.3mにする。コスト+1)。大きくした円が重ならないように、タイヤの回転軸に垂直な4方向の隣のマスには、親以外のブロックを置けません(親とは関節で当たり判定を切っているので、少し重なってもよい)。
どのブロックにも「摩擦オン」を付けられます(摩擦係数2.0、相手と平均せず大きい方を使う。コスト+1)。

| ブロック | コスト | 質量 | 特性 | 脳による制御 |
| --- | --- | --- | --- | --- |
| コア | 0 | 2.0 kg | 必須・1体に1個。正面マーク付き。向きと脱落判定の基準 | なし |
| 基礎 | 1 | 1.0 kg | 標準的な摩擦と反発 | なし |
| 関節 | 3 | 0.5 kg | 1軸ヒンジ。軸は設置時にコア基準の3軸から選ぶ。回り方は「180°」(可動範囲±90°、脳が角度を決める)か「360°」(可動範囲なしで回り続け、脳が回る速さ ±12rad/s を決める。車輪・タイヤ用)を選ぶ | あり |
| 弾力 | 2 | 0.8 kg | 反発係数0.9。親のブロックと、付けた面の向きに伸び縮みするばね(縮み0.15m・伸び0.1m、ばね定数600N/m)でつながり、当たると縮んで相手を弾き飛ばす | なし |
| 雲 | 1 | 0.15 kg | とても軽い。体を大きくしても重くならない | なし |
| 風 | 3 | 1.0 kg | 扇風機のように、吹く向き(既定は付けた面の向き・上下前後左右から選べる)と反対向きの力(自分の重さ + 0.5kg 分)が常にかかる。持ち上げる力(上向きの成分)は、真下に床があるときだけ働き、床に近いほど強い(高さ1mで0)。下に床がなければ持ち上がらないので、空には逃げられない | なし |
| ピストン | 3 | 0.6 kg | 1マス(0.4m)伸び縮みする。伸びる向きは付けた面の向き(既定)・上下前後左右から選べる(親のブロックに向かう向きは不可)。伸びるか縮むかの2通りだけで、途中の位置は指定しない | あり |
| センサー | 1 | 0.5 kg | トレーニング中に地面に触れていると減点(倒れにくい動きを学ばせる)。バトルでは普通のブロック | なし |

組み立てのルール:

- 関節・ピストン・弾力のブロックを挟まずにつながったブロック同士は、1つの剛体(複合コライダー)にまとめる。
- 関節ブロックは、親側の剛体と子側の剛体をヒンジジョイントで接続する。ピストンと弾力はスライドジョイントで接続する。
- 関節とピストンは、合わせて1体につき最大8個(脳の入出力サイズを抑えるため)。
- ブロックの総数は最大24個。

操作(マウスとキーボード):

- 左クリックで面に配置、右ドラッグでカメラ回転、ホイールでズーム。
- Deleteキーで選択ブロックとその先を削除、Ctrl+Zで取り消し。
- 左右対称モード:コアの正面を基準に、反対側にも同じブロックを自動配置する。
- 画面には、現在のコスト、関節数、重心位置を常に表示する。

体を組み直すと運動脳はリセットされます。判断脳は体に依存しない設計(セクション7)なので保持しますが、再トレーニングを推奨する表示を出します。

## 5. 物理シミュレーションと決定性

同じ乱数シードと同じキャラなら、どのPC・どのブラウザでも完全に同じ試合になることを必須要件とします。リプレイ共有、学習中の試合の再表示、将来のオンライン対戦はすべてこの性質に依存します。

物理の基本設定:

- 固定タイムステップ 1/60秒。描画のフレームレートとは切り離す。
- 脳の更新は 1/20秒ごと(3ステップに1回)。出力は次の更新まで保持する。
- 関節は角度制御のモーターとし、脳は目標角度(-1〜1を可動範囲に対応)を出力する。トルク上限を設けて、高速回転のような挙動を防ぐ。
- 脱落判定:コアの中心がタイル上面より1.0m以上下に落ちたら脱落。

決定性を守るためのルール:

- `core/` の中では `Math.random` を禁止し、シード付き乱数(xoshiro128等)だけを使う。
- `Math.sin`、`Math.exp`、`Math.tanh` などはブラウザ間で結果が一致する保証がないため、`core/math/` に自前の近似関数を用意して使う。
- Rapierへの剛体・コライダーの登録順は、設計図のブロックID順に固定する。
- マウス入力や時刻など、外部の値をシミュレーションに入れない。
- テスト:同じ試合を2回実行して状態のハッシュが一致すること、およびPlaywrightでChromium・Firefox・WebKitの結果が一致することを、CIで確認する。

## 6. ステージ:六角タイルと崩落ルール

ステージは半径6の六角グリッド(127枚のタイル)で、3つの崩落ルールが同時に働きます。崩落の流れはすべて試合のシードから決まります。

**タイル**:外接半径0.6mの正六角柱。座標はアキシャル座標(q, r)で管理します。状態は「安全 → 危険マーク(2.0秒) → 崩落」の3段階で、危険マーク中は赤く点滅し、崩落時は下へ落ちて消えます。

**ルールA:安全円の収縮**

- 試合開始時に、ステージ中心から距離4以内のタイルを1枚、最終地点としてランダムに選ぶ。
- 最終地点からの六角距離が安全半径を超えるタイルに、危険マークをつける。
- 安全半径の初期値は、最終地点から最も遠いタイルまでの距離。開始10秒後から、8秒ごとに1ずつ縮み、最小値は1。

**ルールB:滞在による崩落**

- キャラのブロック(コアに限らない)が触れているタイルには、滞在タイマーが溜まる。同じタイルに複数のブロックが触れていても、溜まる速さは同じ。
- 5.0秒に達すると危険マークがつく(コアだけを見ていたときは3.0秒。どのブロックでも溜まるようにしたため延ばした)。
- タイルを離れると、タイマーは溜まる速さの半分の速さで減っていく(2枚のタイルを往復してリセットし続ける戦法を防ぐため)。

**ルールC:ランダム崩落**

- 開始12秒後から、安全円の内側の安全なタイルを1枚ランダムに選び、危険マークをつける(当初は20秒。2026-10-07 に早めた)。
- 間隔は最初4秒で、90秒時点で1秒になるよう直線的に短くする。

**スポーン**:2体はステージ中心を挟んで5マス離れた位置に、向かい合わせで配置し、高さ0.5mから落とします(当初は3マス。2026-10-07 に広げた)。

## 7. 脳の構造:運動脳と判断脳

脳は2層に分けます。判断脳が「どの方向へどの速さで進むか」を決め、運動脳がその指令どおりに関節を動かします。層を分けることで、後のトレーニングが前に覚えた能力を壊す「破滅的忘却」を防ぎ、スキルが積み上がっていく様子をそのまま見せられます。

```
[ステージ・相手・安全円の知覚] → 判断脳(35→24→3) → 指令(方向2・速さ1)
[指令・姿勢・速度・関節・リズム・足元] → 運動脳(17+2J→32→J) → 各関節の目標角度
```

判断脳は運動脳への指令だけを出すので、体を組み直しても判断脳はそのまま使えます。

どちらも隠れ層1層の全結合ネットワーク(MLP)で、活性化関数は `core/math/` の決定論的なtanh近似を使います。更新は1/20秒ごとです。

**運動脳**(体ごとに固有。入力数は 18 + 2×(関節数+ピストン数)、隠れ層32、出力は関節数+ピストン数)

| 入力 | 数 | 内容 |
| --- | --- | --- |
| 指令 | 3 | 進む方向(コア基準の水平2成分)、速さ(0〜1) |
| 姿勢 | 3 | コア座標系で見た重力の向き |
| 速度 | 6 | コアの速度と角速度(コア座標系) |
| 関節・ピストン | 2×(関節数+ピストン数) | 各関節の角度と角速度、各ピストンの伸びと伸びる速さ |
| リズム | 2 | sinとcos。周期は遺伝子の一部として学習する |
| 足元 | 3 | 指令方向の前方3マスが穴かどうか(またぎ用) |
| ジャンプ指令 | 1 | 1 = 跳べ、0 = なし |

出力は各関節の目標角度と、各ピストンを伸ばすか縮めるか(0以上で伸ばす)です。

**判断脳**(体に依存しない。入力77、隠れ層24、出力3)

| 入力 | 数 | 内容 |
| --- | --- | --- |
| 周囲タイル | 61 | 下記の目。安全=0、危険=0.5〜1(崩落が近いほど1)、穴=-1 |
| 自分 | 3 | 足元の滞在タイマーの割合、水平速度(コア基準2成分) |
| 相手 | 7 | 相対位置2、相対速度2、距離、相手の足元が危険か、相手がいるか |
| 安全円 | 5 | 最終地点の方向2、距離、現在の安全半径、自分が円の外か |
| 時間 | 1 | 経過時間の割合 |

出力は運動脳への指令(進む方向2成分を正規化したもの、速さ、ジャンプ指令)です。

**目(周囲タイルの知覚)**:コアを中心に、六角格子4周分(61点、半径約4m)の位置をコアの向きに合わせて回転させ、各点が乗っているタイルの状態を読み取ります。向きを60度単位に丸めないので、キャラが少し回っただけでも見え方が滑らかに変わります。

## 8. 学習アルゴリズム

学習には遺伝的アルゴリズム(ニューロエボリューション)を使います。ネットワークの重みをそのまま遺伝子とし、成績の良い個体を残して突然変異させることを世代ごとに繰り返します。勾配計算が不要で、どんな体型にも同じ仕組みで適用でき、世代ごとの上達が目に見えることが採用理由です。

**1世代の流れ**

1. 個体数64(設定で32〜128)の集団を用意する。初回は現在の脳に小さなノイズを加えた個体で埋める。
2. 全個体を、同じ3つのシードのエピソードで評価し、報酬の平均を適応度とする。シードは世代ごとに変える。
3. 上位4個体はそのまま次世代へ残す(エリート保存)。
4. 残りは、3個体のトーナメント選択で親を選び、重みにガウスノイズ(初期σ=0.05)を加えて作る。交叉は行わない。
5. 最優秀個体のスコアが10世代改善しなければσを0.7倍、改善が続けばσを1.1倍にする(上限0.2)。

**凍結**:トレーニングの対象ではない方の脳は凍結し、遺伝子に含めません。運動脳のトレーニング中は運動脳だけが、判断脳のトレーニング中は判断脳だけが変化します。

**重みの精度**:重みは常にfloat16の精度に丸めて保持します。共有コードを小さくするためで、学習中から丸めておくことで、共有前後で動きが変わらないようにします。

**並列化**:Worker数は `navigator.hardwareConcurrency - 2`(最小2、最大8)とします。各Workerは個体を受け取って評価し、適応度だけを返します。

**保存と再開**:世代が終わるごとに最優秀個体と学習履歴をIndexedDBへ自動保存し、いつでも中断・再開できるようにします。

## 9. トレーニングメニューと解放順

トレーニングは、運動脳は「移動 → 追跡」、判断脳は「危険なタイルを避ける → 生き残り → 押し合い → ライバル練習試合」の順に解放します。「ジャンプ」「穴をまたぐ」は追跡の合格後に挑戦できる任意メニュー、「ライバル練習試合」は合格のない練習用メニューです。運動脳が育つ前に判断脳を鍛えても成果が出ないため、順番解放にしています。合格済みのメニューは、いつでも再トレーニングできます。

| # | メニュー | 鍛える脳 | 内容 | 報酬 | 合格条件 |
| --- | --- | --- | --- | --- | --- |
| 1 | 目標地点への移動 | 運動脳 | 平地。4〜6m先にランダムな目標。指令は目標の方向、速さ1 | 目標への接近量、到達ボーナス、コアが裏返ったら減点 | 3エピソード中2回、15秒以内に到達 |
| 2 | 対象を追う | 運動脳 | 目標が一定速度で逃げ、ときどき曲がる。指令は常に目標の方向 | 距離が縮んだ量、指令方向と実際の移動方向の一致度 | 一致度の平均0.7以上 |
| 3 | 穴をまたぐ(任意) | 運動脳 | タイルのステージに1マス幅の穴の列を並べ、まっすぐ進む指令 | 前進距離、落下で大きく減点。平地での移動エピソードも評価に混ぜる | 穴の列を2つ越える |
| 4 | 崩落ステージを生き残る | 判断脳 | 単独で崩落ルールA・B・Cのステージ。レベル1〜5で崩落ペースが上がる | 生存時間、安全タイル上で毎秒加点、危険タイル上で減点 | レベル3で、9回中3回60秒生存 |
| 5 | BOTとの押し合い | 判断脳 | BOTとの対戦。相手は段階的に強くなる | 押し出して勝つと大きく(+30)、相手の自滅による勝ちは小さく(+5)加点。押し出されて負けると大きく減点(-30)、自滅は-20。相手に近づく・触れていると加点。相手を危険タイルや円外へ近づけた量、自分の生存項 | 標準BOTに勝率30%以上(10戦3勝) |
| 6 | ライバル練習試合(任意) | 判断脳 | 対戦相手プール(受け取ったキャラ・過去の自分)と押し合う。世代ごとに相手を替える | 押し合いと同じ | なし(練習用) |
| - | ジャンプ(任意) | 運動脳 | その場に立ち、一定間隔のジャンプ指令で跳ぶ | 指令から1秒以内のコアの上がり幅。指令がないのに跳ねたら減点 | 上がり幅の平均0.25m以上 |
| - | 危険なタイルを避ける | 判断脳 | 崩落ルールは動くが床は崩れない。崩れたはずのタイルは踏んではいけない床として残る | 安全なタイルで加点、危険なタイル・崩れたはずのタイルで減点 | 9回中3回、60秒で崩れたはずのタイルに触れた時間が3秒未満 |

**穴をまたぐの忘却対策**:運動脳を追加で鍛えるため、評価エピソードの1つを平地での移動にして、歩き方を忘れないようにします。

**押し合いの忘却対策**:評価エピソードの1つを単独の生き残りにして、押すことに夢中で自分が落ちるキャラになるのを防ぎます。

**押し合いの対戦相手**:

1. 突進BOT:相手のコアに向かって直進するだけのルールベースBOT。
2. 標準BOT:開発側で学習させた判断脳を持つ標準キャラ。
3. 自分の過去のキャラや、受け取った友人のキャラ(対戦相手プールに登録したもの)。

## 10. トレーニング観戦の演出

トレーニング画面の目的は「成長を実感する瞬間」を見せることです。シミュレーションは決定論的なので、Workerが評価したエピソードを、メインスレッドでシードから再現して表示します。

- **ゴースト表示**:直前の世代の上位16個体を半透明で重ねて表示し、最優秀個体だけを実体で目立たせる。
- **成績グラフ**:世代ごとの最高・平均の適応度を折れ線で表示する。
- **速度切り替え**:表示を1倍・4倍・描画なし(学習のみ最大速度)で切り替える。
- **マイルストーン**:「初めて立った」(コアの高さを3秒維持)、「初めて目標に到達」、「初めて穴をまたいだ」、「60秒生き残った」、「初勝利」で演出を入れ、その瞬間のリプレイを自動保存する。
- **比較リプレイ**:第1世代と最新世代を左右に並べて同じシードで再生する。
- **脳の様子(任意機能)**:各ニューロンの活性を小さなパネルで表示する。
- **放置学習**:タブが非表示でもWorkerで学習を続ける。画面に戻ったら「留守中のハイライト」として、達成したマイルストーンと成績グラフの変化を見せる。

## 11. バトル

バトルは1対1で、セクション6のステージを使い、先に脱落した方が負けです。プレイヤーは試合中に操作せず、育てたキャラの戦いを観戦します。

- **勝敗**:先にコアが脱落した方の負け。同じステップで両者が脱落した場合は引き分け。
- **時間制限**:150秒。時間切れの場合は引き分け。
- **対戦相手**:BOT、自分の保存キャラ、共有コードで受け取った友人のキャラ。
- **実行場所**:両キャラの脳を含め、すべて自分のブラウザ内で実行する。
- **リプレイ**:シードと両キャラのデータだけで再現できるので、試合後に保存・再生・共有できる。
- **他人のキャラから学ぶ**:対戦した相手を、ワンクリックで押し合いトレーニングの対戦相手プールに登録できる。

観戦画面では、残り時間、安全円の範囲、各キャラの足元の滞在タイマーを表示します。

## 11.5 種目(改善④⑤で追加)

バトルとは別に、育てたキャラで遊べる種目です。どちらも運動脳だけで動き、判断脳は使いません。参加できるのは、トレーニング「対象を追う」に合格したキャラだけです。

**かけっこ**:最大4体が別々のレーンで、20m先のゴールへまっすぐ走ります。ゴールまでのタイム、届かなかったキャラは進んだ距離で順位をつけます(制限時間60秒)。走る人どうしは干渉しません(レーンごとに別の物理ワールド)。

**サッカー(3対3)**:壁で囲まれた 10m×16m のフィールドで、ボールを相手のゴールへ押し込みます。各キャラは自分の運動脳で動き、向かう先はチームの作戦(手書きのAI)が決めます。ボールにいちばん近い1体がボールの後ろへ回り込んで押し込み、1体が自陣のゴール前で守り、もう1体が横で支えます。ゴールが決まったらボールを中央に戻し、90秒で得点の多いチームの勝ち。参加するキャラは、自分・BOT・保存キャラ・受け取ったキャラから選べます。

サッカー用の脳を学習させる仕組みは、今後の追加候補です。

## 12. データ形式と共有

キャラは「設計図+2つの脳+育成状況」を1つのJSONで表します。バージョン番号を必ず持たせ、形式を変えたときは移行処理を書きます。

```json
{
  "version": 1,
  "name": "ころがりくん",
  "blueprint": {
    "blocks": [
      { "id": 0, "type": "core", "parent": null },
      { "id": 1, "type": "joint", "parent": 0, "face": "+x", "axis": "z" },
      { "id": 2, "type": "grip", "parent": 1, "face": "-y" }
    ]
  },
  "brains": {
    "motor": { "inputs": 19, "hidden": 32, "outputs": 1, "rhythmPeriod": 1.2, "weights": "<float16のbase64>" },
    "decision": { "inputs": 35, "hidden": 24, "outputs": 3, "weights": "<float16のbase64>" }
  },
  "progress": { "passed": ["move", "chase"], "generations": { "move": 140, "chase": 85 } }
}
```

**共有方法**:

- **URL共有**:JSONをgzip圧縮(CompressionStream)してbase64url化し、`#c=` の後ろに付けたURLを作る。関節8個の最大構成でも約7千文字に収まり、URLとして問題なく扱える。
- **ファイル共有**:`.monster.json` としてダウンロード・読み込みできるようにする。
- 受け取ったキャラは読み取り専用で保存し、対戦と対戦相手プールへの登録だけを許可する。

**ローカル保存**:IndexedDBに、キャラ、学習履歴(世代ごとのスコア)、マイルストーンのリプレイを保存します。リプレイはシードと試合時点の両キャラのデータ(数KB)だけを持ちます。キャラを後で再トレーニングしても、過去のリプレイが変わらないようにするためです。

## 付録A. 実装時に決めたこと

仕様書に書かれていなかった点や、実装してみて調整した点の記録です。数値はすべて `src/core/config.ts` にあります。

### 物理・キャラ
- 関節モーターは Rapier の ForceBased モデル(ばね定数 1000 N·m/rad、減衰 40、トルク上限 50 N·m)。弱いと、足が床に固定されたとき押し負けて動かなかった。
- コアの正面は +z。左右対称の基準面は x = 0。キャラクリエイト画面では床に正面の矢印も出す。
- 「選択ブロック」はマウスの下にあるブロック(左クリックは配置に使うため)。R キーで関節の軸を切り替える。
- ブロックIDは配列の添字と一致させ、親は必ず自分より小さいIDにする(Rapierへの登録順が一意に決まる)。
- ステージの物理は、残っているタイルの上面と穴の縁の壁を、頂点を共有した1つの三角形メッシュにまとめ、Rapier の FIX_INTERNAL_EDGES で境目を滑らかにする(タイルが崩れたら作り直す)。タイルごとの凸包だと、境目の辺に体が引っかかり、腹ばいで進むキャラはタイルの上でほとんど前に進めなかった(関門2で発見)。
- 2体のスポーンは、中心を挟んで2体の間が3マスになる位置(中心から1.5マスずつ。並びの向きはシードで6通り)。当初は「中心から3マスずつ(2体の間は6マス)」と解釈していたが、2体がほとんど出会わなかったため関門2で改めた。
- 2026-10-07:3マスでは開始直後の押し合いだけで決着することが多く(決着の中央値23秒、4割がランダム崩落の前)、崩落ステージでの判断が勝敗に効いていなかったので、2体の間を5マスに広げ、ランダム崩落の開始を20秒から12秒に早めた。
- 姿勢の報酬は、コアが球なら掛けない(転がって進んでよい)。コアが横向きの円柱なら、円柱の軸まわりの転がりは減点せず、傾きは軸が水平からずれた量で測る。
- 判断脳の入力に「相手との接触」4つを追加(入力77 → 81。データ形式8):2体のブロックが触れているか・相手が近づく速さ・いちばん近いブロック同士の距離・相手の周り(自分のマスと隣の6マス)の危険度。これまでは相手のコアの位置・速さ・距離・足元の危険度しか見ておらず、触れているかや崖っぷちかは判断できなかった。古い判断脳は、足した入力の重みを0にして移行する(動きは変わらない)。
- 判断脳の入力に「相手の向きと体の形」9つと「体の傾きと回転」12を追加(入力81 → 102。データ形式10、2026-10-08)。相手の向きと体の形:相手の正面の向き(自分の向き基準の2成分)・こちらを向いているか(-1〜1)・重さの比べ((相手-自分)/(相手+自分))・相手のコアから、自分の側・反対側・両横へ体がどこまで伸びているか(4つ)・体の高さ。体の傾きと回転:自分と相手それぞれの、コアの上が向いている方向(3成分。立っていれば (0,1,0)、ひっくり返ると上下が -1)と回転の速さ(角速度3成分)。どれも自分の向き基準に直す。古い判断脳は、足した入力の重みを0にして移行する(動きもランクマッチの結果も変わらないことを確認済み)。体の形の違いへの対応を覚えるには、形の違う相手と戦う必要がある(ライバル練習試合で対戦相手プールの相手と練習する)。
- 押し合いの相手は、突進BOT・標準BOT・過去の自分(20世代ごとに、その時点の最優秀の判断脳に入れ替える。自己対戦)を、評価エピソードごとに順番に替える。合格の確認は、突進BOTと標準BOTのそれぞれと10戦ずつして、どちらにも3勝以上。以前は標準BOTだけだったので、突進BOTに勝てなくても合格できていた。
- 判断脳のメニューは、1世代の評価を5エピソードにし、さらに上位4個体だけ5エピソード追加して、合わせた平均で選び直す(運のよい個体が選ばれにくくする)。運動脳のメニューは3エピソードのまま。
- 作戦タイプ(押し合い・ライバル練習試合):バランス(これまでと同じ)・攻め(押し出して勝つ報酬2.5倍、近づく・触れる報酬2倍)・守り(生存の加点5倍、自滅の減点2倍、危険なタイルの上で減点)。育成状況に保存する。
- 脱落の原因は、2体のブロックが実際に触れてから2秒以内に落ちたら「押し出された」、それ以外は「自分で落ちた」。

### 学習
- 目標の方向を、キャラの正面から見た全周を評価エピソード数で等分して割り当てる(3回だけだと正面の目標に偶然届いて合格してしまうため)。
- 合格の確認:世代の最優秀個体が条件を満たしたら、新しいシードのエピソードでもう一度評価する(移動・穴は9回中6回、危険なタイルを避ける・生き残りは9回中3回、追跡は9回の一致度の平均、押し合いは10戦3勝)。
  - 2026-10-06:危険なタイルを避ける以降(避ける・生き残り・押し合い)は合格しにくかったため、必要な回数を半分にした(9回中6回 → 3回、10戦6勝 → 3勝)。
- 追跡の一致度は、直近1秒の指令方向の平均と、同じ1秒の変位(実際の移動方向)の内積で測る(瞬間の速度は歩行で左右に揺れるため)。
- σ の下限は 0.02(評価が揺れるため「改善なし」と判定されやすく、下限が小さいと学習が止まった)。
- 生き残りはレベル1から始め、合格の確認に通るたびにレベルを上げる。レベル3で通ったら合格。レベルごとの崩落ペースは 0.4・0.5・0.6・0.8・1.0 倍で、レベル5がバトルと同じ(安全円の縮小とランダム崩落の進み方)。
  - 関門2の調整:バトルのペースでは60秒時点で安全円の中の安全なタイルが平均14枚しか残らず、手書きの回避ルールでも 5/16 しか60秒生き残れなかった。当初は「レベル3 = バトルのペース」としていたが、合格がほぼ不可能だったため変更した。
- 押し合いの相手は 突進BOT → 標準BOT(合格の目標)→ 対戦相手プール の順。
- 評価の仕事は個体2つずつに分け、空いた Worker から順に渡す(性能の違うコアが混ざるCPUでも遅いコアを待たない)。
- 「初めて立った」:コアの上方向の鉛直成分 0.9 以上、高さ 0.5m 以上を3秒保つ。

### 改善①(2026-10-06、テストプレイのフィードバックによる)
- 崩落ルールBの滞在タイマーを、コアの真下だけでなく、キャラのどのブロックでも触れているタイルに溜める(ブロックの中心の高さ 0.3m 以下を「触れている」とみなす)。

- 運動脳の入力にジャンプ指令、判断脳の出力にジャンプ指令を追加(データ形式バージョン3。古いキャラは重み0で移行し、動きは変わらない)。
- トレーニング「ジャンプ」(任意)、「危険なタイルを避ける」、「ライバル練習試合」を追加。「穴をまたぐ」は穴の手前でジャンプ指令を出す。
- 押し合いの相手は突進BOT → 標準BOTだけにし、対戦相手プールはライバル練習試合で使う。
- 運動脳に「速さ」の指示を守らせる学習は、報酬の設計が複雑になるため見送った(今後の課題)。

### コアが回ってしまう対策(2026-10-06)
- 関節のモーターの反動でコアが回る(左右の関節を同じ向きに振ると、反動が足し合わされる)。物理としては正しい動き。
- 運動脳のトレーニング(移動・追跡・ジャンプ・穴をまたぐ)に**姿勢の報酬**を追加:コアの傾きが30°を超えた分、前後・左右に転がる回転が 2 rad/s を超えた分を減点する(向きを変える回転は減点しない)。
  - 左右2本脚の体で80世代ずつ学習させて比べると、報酬なしでは3つのシードのうち2つが「転がって進む」動きを覚え(転がる回転 約20 rad/s)、報酬ありでは 0.7〜2.9 rad/s に収まった。
  - はじめは許容範囲なしにしたところ、まったく動かないことを覚えてしまったため、許容範囲を設けた。
- コアの回転を物理で減衰させる設定(`CREATURE.coreAngularDamping`)も用意したが、既定は0(オフ)。2本脚の体で10にしても傾きは 55° → 51° にしか減らなかった(脚が地面について支点になり、モーターがコアを振り回すため)。コアを直立に戻す力を加える方法も試したが、モーターと押し合って転びやすくなった。

### ランクマッチ(2026-10-06)
- プレイヤー名を登録し、1人1体のモンスターを登録する。30分ごとの自動トーナメント(最大8体、勝ち抜き戦、3分ごとに1試合)で、全員のブラウザで同じ試合が同じ時刻に流れる(ライブ配信)。
- 日程・出場者・組み合わせ・シードは時刻と登録内容から決定論的に決まる(`src/core/ranked/tournament.ts`)。試合は画面を開いているブラウザが計算して報告し、多数決で正式な結果にする。サーバーでの再計算はしない(`docs/ONLINE.md` の未対応を参照)。
- ランキング:レート(Elo、初期値1500、K=32。引き分けは0.5)・勝利数・かけっこの公式記録(20m、決まった3シードの最速タイム)。数値は `config.ts` の `RANKED`。
- 記録とレートはモンスターごと(プレイヤー + キャラの id)。出場するモンスターを替えても、前のモンスターの記録は残る。
- ランダムマッチ(種目の画面):サーバーがまだ戦っていない相手を選び、同じ2体は1回だけ戦う。レートはトーナメントとは別に計算し、ランキングは部門を切り替えて見る。オンライン画面の「ランダムに探す」はレートに関係しない。

### ブロックの拡張と画面の整理(2026-10-07)
- すべてのブロックに形(立方体・球・円柱)と摩擦オンを追加。グリップブロックは廃止し、古いデータのグリップは読み込むときに「基礎 + 摩擦オン」に変換する(コスト2・重さ1.0kg・摩擦2.0で、動きは変わらない)。データ形式はバージョン4。
- 雲ブロック(軽い)と浮力ブロック(上向きの力)を追加。浮力ブロックは、その後(2026-10-07)「風」ブロックに置き換えた:吹く向きを選べ、反対向きに押される。持ち上げる力は真下に床があるときだけ働く(ホバークラフトのように床の上で浮けるが、穴の上やステージの外では浮かない)。古いデータの浮力は「下向きに吹く風」に変換する(データ形式5)。弾力ブロックはばねで伸び縮みするようにした。総コストの上限は40。
- 風の力は物理ステップごとにかけ直す(Rapier の力とトルクは消すまで残り続けるので、両方を消してからかける)。
- 種目・トーナメント・ランダムマッチに出られるのは「2. 対象を追う」に合格したキャラ。判断脳がなければ、バトルでは相手に向かって突進する(突進BOTと同じ作戦)。
- 画面のタブを「あそびかた・キャラ作成・トレーニング・対戦・オンライン・マイキャラ」に整理した。対戦はバトル・かけっこ・サッカー・ランダムマッチ、オンラインはトーナメント配信・ランキング・出場登録・キャラ交換を、タブの中で切り替える。
- 「あそびかた」では、遊び方のまとめと、いまのキャラの進み具合(次にやること)を表示する。初めて開いたときはこのタブから始まる。
- 3D表示(WebGL の描画領域)は、ブラウザが同時に持てる数に上限(Chrome で16個ほど)があり、超えると古いものから捨てられて真っ暗になる。体を編集するたびにトレーニング画面が作り直され、描画領域が増えてキャラ作成の表示が消えていたので、トレーニング画面の3D表示はタブを開いたときに作り、閉じた表示の描画領域はすぐ手放す(`src/render/webglContext.ts`)。失われたときは復旧して描き直す。

### サッカー・かけっこ・ジャンプ(2026-10-07)
- サッカーのフィールドを、ロケットリーグ風に作り直した:縦30m×横18m、柵は高さ5mの半透明で角を丸め(半径3mの円弧を6枚の板で作る)、ゴールは幅6m・高さ3m・奥行き2.5m(大きなキャラでも入れる)。
- ボールは半径0.55m、重力は半分(少し低重力)、速さは9m/sまで。ゴールしたら、フィールドの真ん中の上空7mから落ちてくる。
- サッカー脳(役割ごと:シューター・キャリアー・ブロッカー)を追加した(入力19・中間16・出力3。データ形式9)。入力の最後の3つは「お手本の動き」(その役割の手書きの動き)で、最初の脳はお手本どおりに動くように作る。何も知らない状態からだと、ボールに触れることすら覚えなかったため。
- サッカーのトレーニング(任意。「2. 対象を追う」の合格で解放):
  - シューター:ゴールの7m手前から、相手のブロッカー(自分と同じ体のBOT)が守るゴールにシュートを決める。
  - キャリアー:ボールを拾い、追いかけてくるBOTに取られないように、3m以上前へ運ぶ。
  - ブロッカー:自分のゴールへ飛んでくる4本のシュートのうち、決められるのを1本以下にする。ボールが遠いときはゴール前に戻ると加点。
  - キャラは歩くのが遅い(標準BOTで秒速0.5mほど)ので、練習はゴールやボールの近くで行う。
- 種目のサッカーでは、選手ごとに役割を選ぶ。その役割のサッカー脳を鍛えていればサッカー脳で、なければお手本の動きで動く。
- トレーニング「かけっこ(全力疾走)」(任意・運動脳):20mを30秒以内(3回中2回)。曲がり方を忘れないよう、評価に目標地点への移動を混ぜる。
- 種目「ジャンプ」:3秒ごとの合図で5回跳び、コアの上がり幅の最高記録を競う(最大4体、レースと同じく別々のワールド)。ランキングにもジャンプの公式記録(決まった3シードの最高)を表示する。

### ランクマッチの結果の統一(2026-10-07)
- 端末によってトーナメントの結果とランキングが違う問題があった。原因は、(1) 版の違うページが同じ試合を違う結果で計算して報告し、多数決が端末やタイミングで変わる、(2) ランキングに端末で計算した結果を混ぜていた、(3) 勝ち上がりを端末の計算で決めていた、の3つ。
- 対策:報告に計算の版(SIM_VERSION)をつけ、試合ごとにいちばん新しい版の報告で多数決をとる(supabase/fix-ranked-consistency.sql)。ランキングはサーバーの正式な結果だけで数え、勝ち上がりも正式な結果に従う。サーバーに新しい版の結果があれば、古いページは報告しない。
- 「AIの考え」の矢印は、判断脳を使わない運動脳のトレーニング(移動・追跡・穴をまたぐ など)でも、運動脳への指令の向きを表示する。

### 長距離とジャンプの表示(2026-10-07)
- 種目「長距離」:楕円のトラック(直線 TRACK.straight、半円の半径 TRACK.radius、1周 約41m)を TRACK.laps 周(3周)。最大4体が同じトラックを走る。
- チェックポイントは1周に TRACK.checkpoints 個(最後がスタート・ゴール)。次のチェックポイントだけを数えるので、順番どおりに全部通らないと周回にならない(近道しても進まない)。通過判定は中心から TRACK.checkpointRadius 以内。
- 運動脳への指令は「次のチェックポイントの方向へ全速力」。順位はゴール時刻、次に通ったチェックポイントの数、次に次のチェックポイントへの近さ。
- トレーニング「長距離(トラック)」(任意、かけっこ合格で解放):1周を走る。報酬は次のチェックポイントへ近づいた分+通過ボーナス+周回ボーナス。合格は3回中2回、1周 TRACK.passLapTime 秒以内。
- ランキングに長距離の公式記録を追加:1体だけで決まったシード(TRACK.recordSeed)で3周を走らせたタイム。ゴールできなければ通ったチェックポイントの数で並べる(制限時間+残りの数)。かけっこ・ジャンプと同じく各ブラウザで計算して保存する。
- 「AIの考え」で、ジャンプの指令(ジャンプボタン)を出している間はキャラの上に黄色の上向き矢印と「JUMP」を表示する(ジャンプのトレーニング・種目・判断脳のジャンプ出力)。

### データ
- 運動脳の weights の最後の1個はリズム周期の遺伝子(周期の対数)。`rhythmPeriod` は確認用の値。
- 受け取ったキャラは parseCharacter で、体の検証と重みの数・値の検証を通ったものだけ使う。
