# データの容量と通信

オンライン機能(Supabase の無料プラン)は、データベース 500MB・転送量 月5GB が上限の目安です。
このゲームは「サーバーには小さなデータだけを置き、計算はすべて各ブラウザで行う」ので、ふつうに遊ぶ分には上限に届きません。
ここでは、どこに何がどれくらい置かれ、いつ通信するかをまとめます。

## キャラ1体の大きさ

| もの | 大きさの目安 |
| --- | --- |
| キャラのデータ(体の設計図 + 運動脳 + 判断脳) | 約10KB(上限32KB。サーバーの check 制約で制限) |
| 試合の記録(リプレイ) | 約20KB(シードと、試合時点の2体のデータ) |

試合そのもの(物理シミュレーション)は保存しません。シードと2体のデータがあれば、どのブラウザでも同じ試合を再現できます。

## サーバー(Supabase)に置くもの

| テーブル | 1行の大きさ | 増え方 |
| --- | --- | --- |
| `characters`(オンライン画面の登録) | 約10KB | 1人10体まで。登録し直すと上書き |
| `players`(プレイヤー名) | 約100B | 1人1行 |
| `ranked_entries`(ランクマッチの登録の版) | 約10KB | 登録し直すたびに1行(追記のみ)。1時間に20回まで。ランダムマッチでは、キャラの中身が変わったときだけ新しい版を作る |
| `ranked_reports`(トーナメントの結果の報告) | 約100B | 1試合につき報告した人数分。すでに3人以上が報告した試合には送らない |
| `random_matches` / `random_reports`(ランダムマッチ) | 約150B / 約80B | 1試合1行 + 報告した人数分 |

目安:プレイヤー100人がそれぞれ5回登録し直すと、登録の版は約5MB。トーナメントの報告は1日(48回)で約100KB。
データベースの500MBに届くのは、かなり先です。

## ブラウザ(IndexedDB)に置くもの

マイキャラ・学習の履歴・リプレイは、すべてブラウザの中だけに保存します(サーバーには送りません)。
ランクマッチでは、次のものをブラウザに保存して、同じものを二度取得しないようにしています。

- 登録の一覧・プレイヤー名・試合の結果(次からは前回より新しい分だけを取得する)
- 登録の版のデータ(書き換えられないので、一度取得したら二度と取得しない)
- かけっこの公式記録(登録の版ごとに1回だけ計算する)
- 報告済みの試合(送り直さない)

## いつ通信するか

| 画面・操作 | 通信の内容 | 量の目安 |
| --- | --- | --- |
| ゲームを開く | ゲーム本体(GitHub Pages から。Supabase は使わない) | 約10MB(ブラウザにキャッシュされる) |
| オンライン:画面を開く | 自分の登録の一覧(名前と日時だけ)。最初に開いたときだけ | 1KB未満 |
| オンライン:登録・更新 | キャラのデータを送る | 約10KB |
| オンライン:ランダムに探す | 押すたびに最大8体のデータ | 約80KB |
| ランクマッチ:画面を開く | 新しい登録・名前・結果(前回より新しい分だけ)。同じトーナメントの間に開き直しても取得しない | 変化がなければ1KB未満 |
| ランクマッチ:トーナメントが始まる(30分ごと) | 出場者を決めるために、新しい登録だけを取得。初めて見る出場者のデータ | 1KB未満 + 1体約10KB(1回だけ) |
| ランクマッチ:更新ボタン | 新しい登録・名前・結果 | 変化がなければ1KB未満 |
| ランクマッチ:試合の計算が終わる | 結果の報告(まとめて1回) | 1KB未満 |
| ランダムマッチ:相手を探して対戦 | 自分の版(中身が変わったときだけ約10KB)・相手のデータ(初めての相手だけ約10KB)・結果の報告・新しい分の取得 | 約1〜20KB |

- ランクマッチの通信と計算は、ランクマッチの画面を開いていて、ブラウザのタブが見えている間だけ行います。ほかの画面やタブにいる間は何もしません。
- 一覧や結果を自動で取り直すのは、トーナメントが始まるとき(30分に1回)だけです。それ以外は「更新」ボタンを押したときだけ取得します(続けて押せるのは15秒ごと)。
- リプレイは、ブラウザに保存したデータから再現するので、見るときに通信はしません。

目安:ランクマッチの画面を1日中開いたままにしても、通信は1日あたり1MB未満(新しい出場者のデータを除く)。
